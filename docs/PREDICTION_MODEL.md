# Prediction Model (推定勝率モデル)

`src/domain/prediction/` — すべて純関数。React / DOM / storage / n01 通信に依存しない。
ブラックボックス ML は使わず、各段を式で説明できることを優先する。

> **これは予測モデルである。** 表示する値は「推定勝率」であり、真の勝率ではない。
> UI は整数 % と信頼度 (高 / 中 / 低、低は「参考値」) を併記し、「確実」「必勝」等の語を使わない。

## 1. 選手強度 (`playerStrength.ts`)

単位は PPR (3 ダーツ平均) 点。

```
base     = 3 · Σ w_s·score_s / Σ w_s·darts_s            (Season 重み w: 1.0 / 0.6 / 0.35 / 0.2)
shrunk   = (n · base + k · μ) / (n + k)                n = 重み付き legs, k = PRIOR_LEGS = 30, μ = リーグ平均
form     = clamp(0.25 · (shrunk(今季) − shrunk), ±3)    2 Season 以上のデータがある時のみ
first9   = clamp(0.10 · (First9 − PPR − リーグの First9 差), ±2) × n/(n+k)   First9 がある時のみ
strength = shrunk + form + first9
```

- データなし → リーグ平均 μ (信頼度 低、`imputed`)。**0 にしない。**
- n01 未接続の選手 / 手動 PPR を選んだ選手 → 手動 PPR を 10 legs 分の証拠として shrink (信頼度 低)。
- n01 連携選手でも、今回の分析に成績行が無い場合 (Season の成績が取得できず同期が前回の PPR を残した場合など) は、
  実効 PPR (n01 の前回値、無ければ手動値) を同じく 10 legs 分の証拠として使う (信頼度 低)。どちらも無ければリーグ平均。
- Leg 勝率は対戦相手の強さに強く依存するため**強度には入れない** (説明にのみ使用可能)。
- legs が報告されない場合は darts/24 で legs を見積もる (サンプル数の評価のみ)。

## 2. 1 対 1 (`matchup.ts`)

```
P_leg  = 1 / (1 + exp(−k · (S_A − S_B)))      k = K_LEG = 0.09 / PPR 点 (10 点差 ≈ 71%)
P_game = Σ_{j=0}^{m−1} C(m−1+j, j) · P_leg^m · (1 − P_leg)^j     m = limit_leg_count (不明なら 1)
```

- Cricket は `k × 0.6`、信頼度を 1 段下げる (PPR との相関が弱い)。
- 確率は [0.01, 0.99] に丸める (極端な値を出さない)。

## 3. ダブルス / チーム (`teamMatchup.ts`)

- サイド強度 = 構成員の平均 (5 名以上は最高・最低を除いた trimmed mean)。
- ペア相性 (自チームのみ、キャプテン入力): VERY_GOOD +1.5 / GOOD +0.75 / NEUTRAL 0 / DISCOURAGED −1.5 (全ペア平均)。

## 4. 相手の不確実性 (`opponentContext.ts`)

相手の出場者は未来のため確定しない。ゲームごとに「相手サイド強度の分布」を作り、

```
E[P_game] = Σ_lineup q(lineup) · P_game(自サイド vs lineup)
```

| 人数 | 分布 |
|---|---|
| 1 | 位置モデルの選手分布そのもの |
| 2 | 観測済みペア (重み α = samples/(samples+3)) と、選手分布を独立とみなしたペア (1−α) の混合 |
| 3+ | 観測済みラインナップ (α) と平均場 (Σ シェア·強度) の混合 |

上位 24 通りまで保持し再正規化。これを `OpponentContext` としてオーダーに保存する
(数 KB。生成時点の評価をいつでも再現できる)。

### 4.1 自チームの強度は通常生成にも同じ値を使う (F03)

自チームの選手の強度は `playerStrength` (§1) で求め、**相手最適化の `OpponentContext` と通常生成の
`OrderInput.players[].ppr` の両方に同じ値**を使う (`domain/n01/historyStrength.ts`)。今季の成績が 0〜数件でも、
前季・前々季の成績が recency 重みで効く。手動 PPR・n01 未連携の選手は手入力の値 (`MANUAL_PPR_LEGS` = 10 レッグ相当、LOW)、
分析に成績のない選手は前回同期の値 (LOW)、何もなければ Unknown (参加者の中央値で補完。0 にしない)。
`Player.n01.stats` は今季の集計のまま変えない。生成時の値と由来は `OrderInput.strengthBasis` に残り、
画面の「戦力の根拠」はそれを読む (再計算しない)。

選手の同一性は `opid` が 1 人を指すと確認できた場合だけ Season をまたぐ (docs/N01_MASTER_DESIGN.md §3.4)。

## 5. Match 勝率 (`matchWinProbability.ts`)

ゲーム勝率 `p1..pn` から Poisson-binomial を DP で厳密計算:
`P(win) = P(W ≥ ⌊n/2⌋+1)`、n 偶数なら `P(draw) = P(W = n/2)`。単純平均は使わない。
最適化で 1 つの数値に順位付けする時は `win + 0.5·draw`。

### 独立性の近似 (重要な制約)

同じ選手が複数ゲームに出るため、ゲーム結果は厳密には独立でない (当日の調子が連動する)。
初期モデルは独立と近似し、その旨を UI と本書に明記する。計算は `MatchOutcomeModel` の背後にあり、
共有の調子を持つ Monte Carlo (シード固定) に差し替え可能。

## 6. 信頼度 (`confidence.ts`)

| 対象 | 指標 | 高 | 中 |
|---|---|---|---|
| 選手 | 重み付き legs | ≥ 40 | ≥ 12 |
| 相手オーダーモデル | 重み付き過去試合数 | ≥ 8 | ≥ 3 |
| スロット | 重み付き観測数 | ≥ 6 | ≥ 2.5 |

ゲームの信頼度 = min(スロット, 相手選手強度, 自選手)。Match = ゲームの下側中央値。

## 7. 説明 (`predictOrder.ts`)

各ゲームに「PPR差 (自 / 相手予想)」「First9 補正」「最近の調子」「ペア相性」「相手の予想 (上位 2 名と確率)」
「データの無い選手はリーグ平均」「Cricket は信頼度低」「参考値」を、該当する時だけ付ける。

## 8. Backtest (`backtest.ts`)

- 試合日順に再生し、各予測には**前日以前の試合だけ**を渡す (同日・未来は渡さない。ハーネス側で強制)。
- 指標: Brier / Log loss / 較正バケット (10 分割) / ECE (バケット加重の |平均予測 − 実績|)。
  ゲーム単位と Match 単位。常に 50% 定数モデルと並べる。
- 再現: `npm run backtest` (決定的。ネットワーク不要)。テスト: `src/domain/prediction/calibration.test.ts`。

### 8.1 結果 (Phase 6、フィクスチャ 3 リーグ)

| リーグ | 単位 | n | Brier (model / 50%) | Log loss (model / 50%) | ECE |
|---|---|---:|---|---|---:|
| ATDO-like | game | 312 | 0.2312 / 0.2500 | 0.6549 / 0.6931 | 0.121 |
| ATDO-like | match | 52 | 0.2104 / 0.2500 | 0.6127 / 0.6931 | 0.247 |
| TDO-like | game | 35 | 0.2446 / 0.2500 | 0.6822 / 0.6931 | 0.118 |
| TDO-like | match | 7 | 0.2354 / 0.2500 | 0.6638 / 0.6931 | 0.201 |
| TDA-like | game | 21 | 0.2498 / 0.2500 | 0.6927 / 0.6931 | 0.110 |
| TDA-like | match | 3 | 0.2525 / 0.2500 | 0.6981 / 0.6931 | 0.161 |

較正 (ゲーム、3 リーグ合算 n = 368):

| 予測帯 | 件数 | 平均予測 | 実績 |
|---|---:|---:|---:|
| 30–40% | 5 | 36.3% | 0.0% |
| 40–50% | 116 | 47.5% | 44.8% |
| 50–60% | 228 | 52.9% | 68.0% |
| 60–70% | 17 | 63.2% | 88.2% |
| 70–80% | 2 | 76.3% | 100.0% |

読み方:

- 3 リーグともゲーム単位で 50% 基準線より悪くない。TDA-like の Match (n = 3) は基準線をわずかに下回るが、
  件数が少なすぎて判断できない (テストでも断定しない)。
- **モデルは控えめ (under-confident)**: 予測が 50% 寄りで、実績はそれより大きく偏る。
  「言い過ぎ」の方向には外れていない — テストは「十分な件数の各バケットで、予測の 50% からの距離が
  実績の距離 + 0.05 を超えない」ことを保証する (過信の検出)。

### 8.2 定数の感度 (ATDO-like ゲーム、Brier)

`priorLegs ∈ {20, 30, 45}` × `k ∈ {0.07, 0.09, 0.11}` × recency `{1/0.8/0.6, 1/0.6/0.35, 1/0.4/0.2}` の 27 通り:
Brier 0.2214–0.2400 (既定 0.2312)。**全通りで基準線 0.25 より良く、既定からの差は 0.01 未満**
(テストの許容は 0.015)。

### 8.3 定数を合成データに合わせない理由

格子では「縮約を弱く・k を大きく」するほど Brier が良くなる。これは合成データの勝敗が
**真の PPR だけ**から生成されるため (データを信じるほど当たる世界)。実リーグでは PPR 以外の要因
(調子・相性・会場・Cricket 比重) が大きく、同じ調整は**過信**に直結する。
したがって既定値は変更しない。実リーグのデータで同じ手順 (`npm run backtest` の格子) を回してから決める。

## 9. 予測の限界 (必ず読むこと)

1. **実リーグで未較正。** 上記の数値はすべて合成フィクスチャ上のもので、パイプラインの正しさと
   回帰の検出を示すだけである。n01 の実データでの精度は未測定 (この環境から n01 に接続できなかった)。
2. **控えめに出る。** 合成データ上では予測が 50% 寄り。画面の「推定勝率 55%」は、実力差が実際より
   小さく見積もられている可能性がある。順位付け (どちらの案が良いか) には使えるが、値そのものを
   勝てる確率と読まないこと。
3. **独立性の近似。** Match 勝率は各ゲームを独立とみなして合成している (§5)。同じ選手が複数ゲームに出るため、
   実際の結果は連動する。
4. **PPR 以外はほぼ見ていない。** Leg 勝率・当日の調子・ペアの実績・会場・投げ順は強度に入らない
   (Season 間の差による調子補正は ±3 点まで、ペア相性はキャプテン入力のみ)。Cricket は PPR との相関が弱く、信頼度を 1 段下げている。
5. **相手の出場は推測。** 相手オーダーは過去の出場位置からの分布であり、当日の欠席・戦術変更は分からない。
6. **データが少ないと 50% に寄る。** 0〜1 試合・少ない legs・新しい選手はリーグ平均に縮約され、信頼度は低
   (「参考値」)。対戦相手の影響もその分弱めて最適化する (OPPONENT_OPTIMIZER.md §3)。
