# Prediction Model (推定勝率モデル)

`src/domain/prediction/` — すべて純関数。React / DOM / storage / n01 通信に依存しない。
ブラックボックス ML は使わず、各段を式で説明できることを優先する。

> **これは予測モデルである。** 表示する値は「推定勝率」であり、真の勝率ではない。
> UI は整数 % と信頼度 (高 / 中 / 低、低は「参考値」) を併記し、「確実」「必勝」等の語を使わない。

## 1. 選手強度 (`playerStrength.ts`)

単位は PPR (3 ダーツ平均) 点。

```
base     = 3 · Σ w_s·score_s / Σ w_s·darts_s            (Season 重み w: 1.0 / 0.6 / 0.35 / 0.2)
shrunk   = (n · base + k · μ) / (n + k)                n = 重み付き legs, k = PRIOR_LEGS = 30, μ = リーグ平均
form     = clamp(0.25 · (shrunk(今季) − shrunk), ±3)    2 Season 以上のデータがある時のみ
first9   = clamp(0.10 · (First9 − PPR − リーグの First9 差), ±2) × n/(n+k)   First9 がある時のみ
strength = shrunk + form + first9
```

- データなし → リーグ平均 μ (信頼度 低、`imputed`)。**0 にしない。**
- n01 未接続の選手 / 手動 PPR を選んだ選手 → 手動 PPR を 10 legs 分の証拠として shrink (信頼度 低)。
- Leg 勝率は対戦相手の強さに強く依存するため**強度には入れない** (説明にのみ使用可能)。
- legs が報告されない場合は darts/24 で legs を見積もる (サンプル数の評価のみ)。

## 2. 1 対 1 (`matchup.ts`)

```
P_leg  = 1 / (1 + exp(−k · (S_A − S_B)))      k = K_LEG = 0.09 / PPR 点 (10 点差 ≈ 71%)
P_game = Σ_{j=0}^{m−1} C(m−1+j, j) · P_leg^m · (1 − P_leg)^j     m = limit_leg_count (不明なら 1)
```

- Cricket は `k × 0.6`、信頼度を 1 段下げる (PPR との相関が弱い)。
- 確率は [0.01, 0.99] に丸める (極端な値を出さない)。

## 3. ダブルス / チーム (`teamMatchup.ts`)

- サイド強度 = 構成員の平均 (5 名以上は最高・最低を除いた trimmed mean)。
- ペア相性 (自チームのみ、キャプテン入力): VERY_GOOD +1.5 / GOOD +0.75 / NEUTRAL 0 / DISCOURAGED −1.5 (全ペア平均)。

## 4. 相手の不確実性 (`opponentContext.ts`)

相手の出場者は未来のため確定しない。ゲームごとに「相手サイド強度の分布」を作り、

```
E[P_game] = Σ_lineup q(lineup) · P_game(自サイド vs lineup)
```

| 人数 | 分布 |
|---|---|
| 1 | 位置モデルの選手分布そのもの |
| 2 | 観測済みペア (重み α = samples/(samples+3)) と、選手分布を独立とみなしたペア (1−α) の混合 |
| 3+ | 観測済みラインナップ (α) と平均場 (Σ シェア·強度) の混合 |

上位 24 通りまで保持し再正規化。これを `OpponentContext` としてオーダーに保存する
(数 KB。生成時点の評価をいつでも再現できる)。

## 5. Match 勝率 (`matchWinProbability.ts`)

ゲーム勝率 `p1..pn` から Poisson-binomial を DP で厳密計算:
`P(win) = P(W ≥ ⌊n/2⌋+1)`、n 偶数なら `P(draw) = P(W = n/2)`。単純平均は使わない。
最適化で 1 つの数値に順位付けする時は `win + 0.5·draw`。

### 独立性の近似 (重要な制約)

同じ選手が複数ゲームに出るため、ゲーム結果は厳密には独立でない (当日の調子が連動する)。
初期モデルは独立と近似し、その旨を UI と本書に明記する。計算は `MatchOutcomeModel` の背後にあり、
共有の調子を持つ Monte Carlo (シード固定) に差し替え可能。

## 6. 信頼度 (`confidence.ts`)

| 対象 | 指標 | 高 | 中 |
|---|---|---|---|
| 選手 | 重み付き legs | ≥ 40 | ≥ 12 |
| 相手オーダーモデル | 重み付き過去試合数 | ≥ 8 | ≥ 3 |
| スロット | 重み付き観測数 | ≥ 6 | ≥ 2.5 |

ゲームの信頼度 = min(スロット, 相手選手強度, 自選手)。Match = ゲームの下側中央値。

## 7. 説明 (`predictOrder.ts`)

各ゲームに「PPR差 (自 / 相手予想)」「First9 補正」「最近の調子」「ペア相性」「相手の予想 (上位 2 名と確率)」
「データの無い選手はリーグ平均」「Cricket は信頼度低」「参考値」を、該当する時だけ付ける。

## 8. Backtest (`backtest.ts`)

- 試合日順に再生し、各予測には**前日以前の試合だけ**を渡す (同日・未来は渡さない。ハーネス側で強制)。
- 指標: Brier / Log loss / 較正バケット (10 分割)。ゲーム単位と Match 単位。常に 50% 定数モデルと並べる。
- フィクスチャ (シード付きシミュレーション) での結果 (Phase 3 時点):

| リーグ | ゲーム数 | Brier (model / 50%) | Log loss (model / 50%) | Match Brier (model / 50%) |
|---|---:|---|---|---|
| ATDO-like | 312 | 0.2312 / 0.2500 | 0.6549 / 0.6931 | 0.2104 / 0.2500 |

フィクスチャの結果は**パイプラインの正しさ** (リーク無し・指標計算・基準線比較) の確認であり、
実際のリーグでの精度を示すものではない (データ生成過程がモデルと同族のため)。
実リーグでの較正は n01 に接続できる環境で行う必要がある (Phase 6 参照)。
