# データ分析: シーズン横断の合算・競技種別・役割別分析

対象: `src/features/analytics/`（オーダー生成・戦力推定・n01同期・保存には触れない）

## 1. 何を直したか

| 問題 | 旧実装 | 新実装 |
|---|---|---|
| 形式が違う季を合算できない | `splitByFormat()` が試合形式の署名（レッグ数・開始点数・ディビジョン設定）が完全一致しない季を丸ごと除外 | 除外しない。季ごとに「どのカウンタを採用できるか」を `projection.ts` が決め、Σ分子 / Σ分母 で合算 |
| `match_type` の欠損を 01 とみなす | 共通パーサーが欠損を `'01'` で埋める（スケジュール） | 分析専用のスロット証拠 (`parseSlotEvidence`) で欠損を保持し、`gameKind.ts` で 01 / cricket / unknown を判定 |
| Cricket の Leg/Set が混入 | 公式 `leg` / `set` をそのまま使用 | Cricket を含むディビジョンでは 01 のゲーム記録から数え直し、Keep/Break は採用しない |
| 全期間（上限12・失敗季を古い季で穴埋め） | 取得失敗後も次の古い季を取りにいく | 「直近12季」。失敗した季は窓の位置を占め、置き換えない |
| 役割別の成績がない | — | 01全体 / シングルス / ダブルス / その他（トリオス・ガロン・チーム戦）を切替 |

## 3. データ契約

- 値が無いものは `null`。0 として加算しない。率は Σ分子 / Σ分母（平均の平均はしない）。
- `gameKind.ts`: 優先順位は ①ゲーム自身の `match_type`（試合データの欠損は n01 仕様どおり 01。ただし Cricket スロットと矛盾すれば unknown）②スロットの `match_type` ③開始点数 / 設定の `match_type` ④unknown。名称だけでは決めない。
- `projection.ts`（表示モード × 季 → その季が出すカウンタ）:
  - 01全体・全スロット 01 → n01 公式値そのまま
  - 01全体・Cricket を含むディビジョン → score/darts/F9/ton/HighFinish/BestLeg は公式、Leg/Set は 01 ゲームから再計算、Keep/Break は対象外
  - 01全体・種別不明の枠 → 公式通算は使わず、01 のゲーム記録のみ
  - シングルス / ダブルス / その他 → その種別のゲーム記録のみ。チームはサイド合計、選手はシングルスなら本人の値、複数人ゲームは検証済み復元のみ
  - ゲーム一覧が途中までしか取れなかった季、または **読めない試合記録が 1 件でもある季** は使わない（読めた記録はキャッシュに残すが確定値にしない。理由を「集計の内訳」に表示）
- `reconstruct.ts`: 1 選手 × 1 季で、全 01 ゲームの復元合計が n01 公式値と一致した項目だけ採用（3DA / First 9 / ton / High Finish / Break を項目別に判定）。一致しなければ何も表示しない。Best Leg はシングルスの Leg から開始点数別で、3DA の検証とは別条件: 期間内でその選手が出た全季の、その開始点数のシングルスを **すべて** 復元できた場合だけ確定表示（通信上限・取得失敗・破損データが 1 件でもあれば保留）。
- 公式 Match 勝敗は試合単位の結果のため、Cricket（または種別不明）の枠があるディビジョンの季を含むときは「Cricketの結果を含む（公式）」と注記する（数値は変えない）。

## 4. 通信

| 取得 | いつ | 上限 |
|---|---|---|
| シーズン（tournament / stats ×2 / standings / 名簿） | 期間を開いたとき | 80 回（直近12季 = 1 + 12×5 = 61） |
| ゲーム一覧 `match/list`（100 件/頁、`tmid__regex=_lg_`、古い順） | 種別ビュー、または Cricket・種別不明の枠がある季の 01全体 | 100 回 / 1 季 15 頁 |
| Leg 明細 `match/get` | **ダブルス**: プレイヤー表示で選手が表示され、ゲーム一覧がそろったとき自動（表示中のその選手だけ。ダブルス01の出場がない選手は取得しない）。**その他**（トリオス等）: 「Leg明細から個人成績を復元」を押したときだけ | 60 回 / 1 回の復元 |
| ハイイン記録 `tournament/stats?kind=player_high_in` | 上と同じ自動取得のうち、§8 の主催者規則の範囲内の季でその選手にダブルス01の出場がある季（照合用。無くても集計する） | 1 季 1 回（上の 60 回に含む） |

すべてキャッシュ（完了季 7 日 / 開催中 6 時間、取得途中は 10 分）、オフライン時は期限切れキャッシュ、画面切替・期間変更で中断。季の間で `setTimeout(0)` で描画に譲る。

自動取得（ダブルス）の約束:
- 同じ期間で結果のある選手、取得中の選手は取り直さない（再描画・表示切替・再訪では通信しない）。別の選手を表示すると取得中のものは中断し、その結果は捨てる。結果は期間ごとに持ち、期間・リーグ・チームが変わった後に届いた結果は表示しない。
- 失敗は一度だけ表示し、自動では再試行しない。「取得できなかった明細を再試行」は、失敗・通信上限・未取得がある場合だけ出す（保存済みの明細は使い、足りない分だけ取得）。画面上部の「再取得」の後は、選手ごとに最初の 1 回だけ明細を取り直す。
- 状態の表示: 取得中 / 取得済み / 一部集計（公式値と一致した季だけ） / 取得不可（再試行あり） / 対象なし（ダブルス01の出場なし）。
- 実測（2026-11-15, 固定フィクスチャ・偽 n01）: 2024 2nd の和田 圭司 1 名で `match/get` 14 回 + ハイイン 1 回 = 15 回。相方は共有ゲームとハイインをキャッシュから読む。

## 5. 集計できないもの（推測で埋めない）

- ダブルス・トリオス・チーム戦の **選手個人** の 3DA 等: Leg 明細の復元が公式値と一致した選手・季のみ。全員を同条件で揃えられないため、選手のランキングには含めない（Leg/Set 勝率はペア・チームとしての結果で順位付け可）。
- 種別ビューの First 9・Keep/Break・100+〜180・High Finish（チーム・未復元の選手）: ゲーム一覧に含まれない。
- Cricket を含むディビジョンの Keep/Break: 01 のみと一般には確認できない。
- 複数季の Best Leg: 季ごとの開始点数の構成が異なるときは比較しない。公式値は開始点数の区別がない（ラベルで明示）。
- n01 の帰属規則そのものの限界: ペアが記録せずに投順を入れ替えた場合、n01 の公式値と復元値は同じ誤りを共有し、チェックサムでは検出できない。
- 個人スタート率: イン規則を確認できない枠・季（§8）、投順の照合が取れない季、明細を取得できないゲームは数値にせず、内訳に理由を出す（失敗には数えない）。

## 6. Cricket 対応の拡張点

`metricCatalog.ts` に競技種別ごとの指標（MPR 等は `implemented: false`）。01 の `StatLine`（得点・投数）と Cricket のマーク・ラウンドを混ぜない。追加手順はファイル冒頭のコメント参照。未実装の種別はどの画面にも出ない。

## 8. 個人スタート率（ダブルイン, 2026-11-15）

`startRate.ts`（数え方・期間集計）、`startRule.ts`（イン規則の判定）、`service/detailService.ts`（季ごとの採否）。n01 の公式値ではなく、Leg 明細から算出した値として表示する。

**定義**: 本人がペアをスタートさせたスロー数 ÷ ペアが未スタートの状態で本人が実際に投げた、判定可能なスロー数。1 スロー（最大 3 本）= 1 試行。期間は Σ成功 / Σ試行。ペアの初回スタート率、1 本単位の命中率、着弾位置の推定は扱わない。

**数え方**（Leg ごと・ペアごとに未スタートから）:
- 投げ手は n01 の登録投順で、各 Leg で `order[0]` から交互（§2-5 で公式通算と一致した規則）。
- 開始前に残点が開始点のままの 0 点 → 失敗。最初に得点して開始点を下回ったスロー → 成功。以後のスローは数えない。開始前に一度も投げなかった選手は分母に入らない。
- `match/get` の先頭行（`{score: 0, left: 開始点}`）はスローではない（パーサーが除く）。実スローとして記録された 0 点は失敗（n01 自身がそのダーツを通算に数え、下の TDO 実例でハイイン記録が 0 点の次の投げ手を指す）。
- 相手がチェックアウトで上がり、一度もスタートできなかった場合 → 投げた分はすべて失敗。
- 数えないもの（内訳に Leg 数で表示）: 未終了の Leg、スタートしないままミドル（`middleForDiddle`）など投てき以外で決着した Leg（ATDO 2024 2nd に、15 ラウンド無得点の側に Leg が付いた記録がある）、残点と得点が連続しない記録、開始前のチェックアウト。
- 季ごとの採否: その季の 01 チェックサム（§3 `reconstruct.ts`）で 3DA が採用された選手・季だけ。照合不一致・未取得は「投順の帰属を確認できていない」「明細未取得」として除外。n01 のハイイン記録が同じ Leg（`time` 一致）で別の選手・別の点数を示すゲームは「投順不一致」で除外。

**イン規則の判定**（`startRule.ts`, 2026-11-15 改訂）。根拠の優先順:
1. 試合・Leg の明示設定 — n01 には無い（スケジュール、`match/get`、`match/throws`、API マニュアル https://push.n01darts.com/api/v1/n01_api_manual_ja.html のいずれにも in-rule の項目が無い）。
2. 主催者規則（`DOUBLE_IN_RULES`）: **リーグ ID** と **適用範囲** で照合する（団体名では照合しない）。範囲内の季のダブルス01の枠（`num_part` 2・01・開始点数あり）はダブルイン。ハイイン記録が 0 件（シーズン序盤）でも、取得に失敗しても、そのまま算出する。
3. それ以外 → 「ルール不明」（ダブルインとして数えない）。範囲外の季・開始日が不明な季・未登録のリーグ・ダブルス以外の枠・Cricket・枠の設定が違うものはすべてここ。ストレートインをダブルインとして数えることはない。
