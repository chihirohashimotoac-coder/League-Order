# データ分析: シーズン横断の合算・競技種別・役割別分析

対象: `src/features/analytics/`（オーダー生成・戦力推定・n01同期・保存には触れない）

## 1. 何を直したか

| 問題 | 旧実装 | 新実装 |
|---|---|---|
| 形式が違う季を合算できない | `splitByFormat()` が試合形式の署名（レッグ数・開始点数・ディビジョン設定）が完全一致しない季を丸ごと除外 | 除外しない。季ごとに「どのカウンタを採用できるか」を `projection.ts` が決め、Σ分子 / Σ分母 で合算 |
| `match_type` の欠損を 01 とみなす | 共通パーサーが欠損を `'01'` で埋める（スケジュール） | 分析専用のスロット証拠 (`parseSlotEvidence`) で欠損を保持し、`gameKind.ts` で 01 / cricket / unknown を判定 |
| Cricket の Leg/Set が混入 | 公式 `leg` / `set` をそのまま使用 | Cricket を含むディビジョンでは 01 のゲーム記録から数え直し、Keep/Break は採用しない |
| 全期間（上限12・失敗季を古い季で穴埋め） | 取得失敗後も次の古い季を取りにいく | 「直近12季」。失敗した季は窓の位置を占め、置き換えない |
| 役割別の成績がない | — | 01全体 / シングルス / ダブルス / その他（トリオス・ガロン・チーム戦）を切替 |

## 2. 実データで確認した事実（2026-10-13, n01 読み取りAPI）

ATDO DARTS LEAGUE (`lg_l3hI_3397`)。数値はすべて `realData.roles.test.ts` でフィクスチャとして固定。

1. **2024 2nd (`t_kY1n_6823`)** は `match_type` がどこにも無い。スロット `8kxb`「クリケット」は `startScore: 0`。`match/list?schid=8kxb` は 0 件だが `lg_result` は 1 試合 7 ゲームを数える → Cricket は試合記録なしで結果入力されている。
2. 同季 Desperado (`pzDR`) の 01 記録 48 ゲームの合計は **score 48844 / darts 3559 で公式 `stats_list` と完全一致**。一方 Leg 102 / Set 48 に対し公式は 120 / 56（+18 Leg, +8 Set = 1 試合 1 枠の Cricket）。
3. 01 シングルス 2 ゲームと Cricket に出た選手（伊集院）: 公式 score / darts / First 9 / 100+・140+ / High Finish / Best Leg は 01 のみの値と一致、Leg は 9（01 は 4）。ton は排他区分（100–139 / 140–169 / 170–179 / 180）。
4. **2026 3rd (`t_ABvC_5234`)** は全スロット `match_type: "01"`。A ディビジョン（`game_setting.round = 0`）だけ別 `schid`・シングルス先取 3。ドリズム (`WpZb`) 14 ゲームの合計は score / darts / Leg / Set すべて公式と一致。
5. **個人帰属**: Leg 明細 (`match/get`) はサイド単位の訪問で、投げた選手は記録されない。「各 Leg で `order[0]` から交互、先頭の 0 点ダミーラウンドも 1 訪問」の規則だけが公式の個人通算を再現する（和田 8298/635、阿部 1222/74、灰田 473/26 + First 9・ton・High Finish・Break まで一致、柴田 2117/99）。「Leg を跨いで継続」「Leg 毎に先頭交代」は不一致。ペアの投順を入れ替えるとチェックサムが崩れる。
6. 公式 Best Leg はダブルス等の Leg を含まない（灰田はペアで 2 Leg 勝って Best Leg なし）。

## 3. データ契約

- 値が無いものは `null`。0 として加算しない。率は Σ分子 / Σ分母（平均の平均はしない）。
- `gameKind.ts`: 優先順位は ①ゲーム自身の `match_type`（試合データの欠損は n01 仕様どおり 01。ただし Cricket スロットと矛盾すれば unknown）②スロットの `match_type` ③開始点数 / 設定の `match_type` ④unknown。名称だけでは決めない。
- `projection.ts`（表示モード × 季 → その季が出すカウンタ）:
  - 01全体・全スロット 01 → n01 公式値そのまま
  - 01全体・Cricket を含むディビジョン → score/darts/F9/ton/HighFinish/BestLeg は公式、Leg/Set は 01 ゲームから再計算、Keep/Break は対象外
  - 01全体・種別不明の枠 → 公式通算は使わず、01 のゲーム記録のみ
  - シングルス / ダブルス / その他 → その種別のゲーム記録のみ。チームはサイド合計、選手はシングルスなら本人の値、複数人ゲームは検証済み復元のみ
  - ゲーム一覧が途中までしか取れなかった季は使わない（部分集計として明示）
- `reconstruct.ts`: 1 選手 × 1 季で、全 01 ゲームの復元合計が n01 公式値と一致した項目だけ採用（3DA / First 9 / ton / High Finish / Break を項目別に判定）。一致しなければ何も表示しない。Best Leg はシングルスの Leg から開始点数別。

## 4. 通信

| 取得 | いつ | 上限 |
|---|---|---|
| シーズン（tournament / stats ×2 / standings / 名簿） | 期間を開いたとき | 80 回（直近12季 = 1 + 12×5 = 61） |
| ゲーム一覧 `match/list`（100 件/頁、`tmid__regex=_lg_`、古い順） | 種別ビュー、または Cricket・種別不明の枠がある季の 01全体 | 100 回 / 1 季 15 頁 |
| Leg 明細 `match/get` | 選手を選び「Leg明細から個人成績を復元」を押したときだけ | 60 回 / 1 回の復元 |

すべてキャッシュ（完了季 7 日 / 開催中 6 時間、取得途中は 10 分）、オフライン時は期限切れキャッシュ、画面切替・期間変更で中断。季の間で `setTimeout(0)` で描画に譲る。

## 5. 集計できないもの（推測で埋めない）

- ダブルス・トリオス・チーム戦の **選手個人** の 3DA 等: Leg 明細の復元が公式値と一致した選手・季のみ。全員を同条件で揃えられないため、選手のランキングには含めない（Leg/Set 勝率はペア・チームとしての結果で順位付け可）。
- 種別ビューの First 9・Keep/Break・100+〜180・High Finish（チーム・未復元の選手）: ゲーム一覧に含まれない。
- Cricket を含むディビジョンの Keep/Break: 01 のみと一般には確認できない。
- 複数季の Best Leg: 季ごとの開始点数の構成が異なるときは比較しない。公式値は開始点数の区別がない（ラベルで明示）。
- n01 の帰属規則そのものの限界: ペアが記録せずに投順を入れ替えた場合、n01 の公式値と復元値は同じ誤りを共有し、チェックサムでは検出できない。

## 6. Cricket 対応の拡張点

`metricCatalog.ts` に競技種別ごとの指標（MPR 等は `implemented: false`）。01 の `StatLine`（得点・投数）と Cricket のマーク・ラウンドを混ぜない。追加手順はファイル冒頭のコメント参照。未実装の種別はどの画面にも出ない。

## 7. 検証コマンド

- `npm run verify:analytics-roles [tdid…]` — ライブの n01 に対する読み取り専用の照合（CI 対象外。終了コード 0 / 1 不一致 / 2 接続不可）
