### 作業のコツ・注意

- E2E は `npx playwright test <spec> --trace off`。webServer は `npm run build && vite preview` を使い、起動中のサーバーを再利用する。コードを変えたら `pkill -f "vite preview"` してから実行する（古いビルドで走らないように）。E2E の実行中に `npm run verify`（build を含む）を走らせると、配信中の `dist/` が置き換わるので避ける。
- 既存 E2E の回帰一式（約 20 分）：harimaru・browse・setMatch・matches・liveFollow・n01・a11y・order・share・analyticsViewports・start・themes・teamHeader・viewerNav・people。
- プレビューの Artifact 更新：`PREVIEW_DEMO_N01=1 npm run build:preview` → `dist-preview/index.html` の head から charset・viewport・title を除き、`<title>` を付けて本文に `<div id="root"></div>` だけのページにする → `assets/*` とアイコンを `files` で同じ Artifact に publish（古いハッシュのファイルは `null` で消す）。index.html をダブルクリックで開く（file://）と真っ白になる（モジュールが読めない）のは仕様。
- サンプル読み込み後、アプリはホームを少し下へスクロールする（既存の動作）。E2E では `scrollTo(0, 0)` してから確かめる。
- `page.clock` を使うと CSS アニメーションは実時間のまま進む。入場アニメーションの終了は実時間で待つ（1.5 秒）。
- 乱数・時計を固定する E2E：`e2e/seededRandom.ts` の `seedRandom(page, 種)` で `Math.random` を置き換え、`page.clock.install({ time: 固定の時刻 })` と `page.clock.pauseAt(...)` を**読み込みの前**に呼ぶ。時計は `runFor` だけで進める（実時間で進むと、カーソルの速さ・抽選の時刻と回数が実行ごとに変わる）。静かな行動を待つときは、実時間の待機ではなく `runFor` で進める（眠りは最長 40 秒）。気まぐれな歩き方は種によって向きが偏るので、左右の両方向などの決まった条件は `controller.dom.test.ts` で決まった乱数を使って確かめる。
- 動作を狙って再生する確認：開発サーバー（`npx vite`）では `window.__harimaru`（`HarimaruController`）が出る（`import.meta.env.DEV` のときだけ。本番ビルドには含まれない）。`__harimaru.trigger('slip')` などで、いつもと同じ安全の確かめを通して動作を始められる（できなければ `false`）。`__harimaru.snapshot()` で状態を読む。E2E は本番ビルドで動くので使えない。

## 5. 設計上の判断（PR2 以降の前提）

- 足場の帯（上辺から 20px＋余白 3px）に、ボタン・リンク・入力・色/枠付き要素の箱、または文字の矩形が少しでも入る x 範囲は使わない。カード間 14px の隙間には立てないため、ホームで実際に使えるのは主に「観戦・分析」タイル列の上（見出し文字の右）と、上が空いたカードの上辺。
- 足場をつなぐのは、各足場の両端から角丸の余白（`cornerInset` 12px）を除いた範囲どうしが 1px 以上重なるときだけ（`terrain.ts` の `mergePlatforms`、`params.ts` の `minJoinOverlap`。2026-11-25 から）。隙間のある・端が接するだけ・角丸が浅く重なるだけのカードは、別々の足場。継ぎ目では、歩き・駆け足は足場の端で止まり、渡るのは既存の安全条件（経路の障害物・見える範囲・隙間と高さの上限）を満たすジャンプだけ。それまでは隙間 12px 以下を 1 本につないでいたため、PC のホームのタイル列（隙間 10px・角丸 16px）の隙間と角丸の上を、足元の高さが変わらないまま歩いていた。
- ページは window スクロール。レイヤーは body 直下 absolute のため、スクロールに JavaScript なしで追従する。足場が見えない位置では出ず、スクロール停止時に見える足場があれば移る。
- 休止：タブ非表示・モーダル/シート（`[aria-modal="true"]`, `.sheet-backdrop`）・画面外。モーダル検出は MutationObserver（`.app` の childList）。
- 足場 (タイル・カード) がホバーなどで動くときは、消さずに真下の足場の上辺に合わせて一緒に動く (毎フレーム追従)。足場以外の要素がキャラクターの周りで動くときだけ隠す。上辺の差 3px 以内は同じ列として扱う (`rowTolerance`)。ユーザーのプレビュー確認で「ボタンにホバーすると消える」と指摘され、隠す方式から変更した (2026-11-18)。
- 横スクロールするカルーセルは足場にしない（スクロールイベントが window に届かず位置が追えないため）。
- 入場アニメーション中は計測しない（有限の Web Animations が動いている間は待つ。最大 3 秒）。
- サンプル読み込み後、アプリは既存の動作でホームを少し下にスクロールする。PC の低い画面（1280×720）ではその位置に足場がなく、ハリマルが出ないのは正しい動作。

### 設計上の判断

- **登場の端**：スクロールで体が完全に抜けた端（上・下）はその端だけ（経路がなければ元の位置に残って待つ。逆スクロールで元の位置が見えれば、その場の続き）。画面遷移・初回は左右（前の画面でいた位置に近い側から。なければ乱数）。~~左右のどちらにも経路がないとき、上下の端も使う（`sideEntryFallback: true`）~~ → §10 で廃止（初回・画面遷移は左右だけ）。
- **左右の端**：立てる範囲が端に届いていれば歩いて、隙間があれば端の向こうから小ジャンプで入る（足は端の向こうに隠れたまま踏み切る。隙間の上限 `entryMaxGap` 120px → §10 で、画面の端と要素の間の実際の空白 24px に変更）。端で見えるのは 6・12px（耳と目）。
- **上端**：`peekTop` で頭から見せ、`dropAir` で落ち（加速）、`dropLand` で四足で受け止める（上限 `entryMaxDrop` 240px）。固定ヘッダーの裏（z-index が下）から出る。
- **下端**：画面の下へ続く要素の側面の横で耳と目から見せ、`sideMount` → `sideClimb` → `sideLedge` → 既存の `climb` で上辺に乗る（上限 240px）。セルを文書の下端より下に置かない（スクロールできる範囲を広げない）。
- **側面**：前足は側面の線の上（組ごとに同じ前足の高さ、組ごとに約 6px 上げる。最後の組は上辺の高さ）。`sideLedge` と climb の初コマは同じ角。climb の後半は前足を上辺の内側へ移し（治具の 1〜1.5 倍）、最後のコマの位置で待機に戻る。立てる範囲に収まらなければ、そこから歩く。体は画面の左右の端から 8px まで外へ出てよい（`edgeOverhang`、出た部分は描かれない。スマホの 12px の余白で側面を登るため）。
- **候補の要素自身・包む入れ物**：出発・着地・つかまる要素自身の箱は、背景色・枠だけの飾りの要素なら 3px（`decorAllowance`）まで重なってよい（要素で見分ける。操作部品・背景の画像・疑似要素の内容がある要素は縮めない）。側面をつかむ要素（操作部品を除く）と、出発・着地の要素を包む入れ物（カードの中の枠など）は、背景色・枠の箱を数えない（背景の画像・疑似要素の内容・中の文字・部品・周りの要素は数える）。観戦のライブ画面（スマホ）は足場がすべてフォーカスカードの中にあり、カードの箱を数えると端から入れなかった。ボタンの側面はよじ登らない（面を透かさないため、登る途中の体が収まらない）。例外（PR3 から）：入れ物が調べる範囲を完全に包み、実際にスクロールしない場合は、背景の画像も含めて入れ物の箱を数えない（`collectObstacles` の `behind`）。直下に文字がある要素の箱は縮めない。
- **角丸**：足場の両端から除く幅は、要素の上辺の角丸の半径と `cornerInset`（12px）の大きい方（`.btn.xl` など半径の大きい要素の曲線を歩かない）。
- **端の意図の固定**：登場を始めた端（のぞいて引っ込んだ端を含む）は、中断のあともその端だけから入り直す（ふさがれたら画面の外で待つ）。
- **フォーカスの輪**：フォーカスの輪が出ている要素の上には立たず、輪は要素の外側 4px まで障害物として数える。フォーカスが移ったら、経路の途中なら中断し、立っていればその場を確かめ直す。
- **中断の契機**：スクロール・リサイズ・DOM の変化（中身・クラス・hidden・open・インラインの style・文字）・位置の変わるトランジション・フォーカスの移動で、経路の再生（登場・移動）を中断して隠れ、同じ意図の端から入り直す。スクロールの途中は登場を始めない。
- **移動の選び方**：経路の余裕（0・2・4・8px）がある・近い経路ほど選ばれやすい。直前に渡った 2 つの要素の間は 30 秒間 0.15 倍（往復の抑制）。安全な候補が少ないときは移動の重みを下げる。準備のあと 15% で見送り（一歩戻る／伏せる）。
- **計測**：DOM の全体の走査は、行動を選ぶとき・登場を試すとき（変化を契機）だけ。経路の再生中は、着地・つかまる要素の位置だけを毎フレーム確かめる。
