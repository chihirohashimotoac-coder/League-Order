# Opponent-Aware Optimizer (対戦相手最適化)

プリセット `OPPONENT_OPTIMIZED` (表示名「対戦相手最適化」)。次戦の相手の出場予測に対して、
**推定 Match 勝率**が最も高くなるオーダーを探す。予測モデルは [`PREDICTION_MODEL.md`](./PREDICTION_MODEL.md)。

## 1. 入力

`OrderInput.opponent: OpponentContext` (任意)。SETUP で、キャッシュ済みの Match Intelligence と
選択したフォーマット・選手から作られ、オーダーと一緒に保存される (数 KB)。

- 自選手の予測強度 (PPR 点) と信頼度
- ゲームごとの相手サイド強度の分布 (和 1)・試合形式 (先取レッグ数・Cricket)・信頼度
- 相手名・試合 ID・日付・生成時刻

保存済みオーダーは `opponent` を持つため、ライブのキャッシュが無くても同じ数値で再評価できる。

## 2. 目的関数

既存の加法スコアに 1 項を加える (`src/optimizer/scoring/score.ts`):

```
Score = … 既存の各項 … + w_opponent · OpponentWin
OpponentWin = mean_g E[P_game(自サイド vs 相手分布)]      (= 期待勝ちゲーム数 / ゲーム数)
```

- Combo ごとに前計算 (`Combo.oppWin`)、分枝限定の上界は各ゲームの最大値の和 (他の項と同じ扱い)。
- 予測と最適化は**同じ関数** (`sideStrength` + `expectedGameWin`) を使うため、画面の推定勝率と
  最適化の内部値は一致する。
- 他のプリセットは `w_opponent = 0`。加算は厳密に `+0` で、**探索・数値とも従来と同一**
  (テスト: 相手データの有無で他プリセットの配置・総合値が変わらない)。

## 3. 重みとロバスト化

| 重み | strength | gameFit | pairFit | fairness | roleFairness | novelty | consecutive | season | opponentWin |
|---|---|---|---|---|---|---|---|---|---|
| 対戦相手最適化 | 0.3 | 0.45 | 0.35 | 0.9 | 0.3 | 0 | 0.5 | 0.05 | 2.4 |

- 公平性 (fairness / roleFairness / consecutive) は**バランスと同水準の Soft 項**として残す。
  推定勝率が置き換えるのは主に「生の戦力」項であり、公平性ではない。
  これにより「最強選手を全ゲームに出す」退化解を避ける (検証: 6 名 8 枠で出場差 ≤ 1、全員出場)。
  > 判断記録: 当初案 (fairness 0.3) では、ダブルス 1 枠の推定勝率 +0.6 が公平性の罰則を上回り、
  > 1 名が 4 回・3 名が 0 回という退化解になった (テストで検出)。バランス水準へ引き上げた。
- **信頼度による減衰**: `effective = base × factor` (HIGH 1.0 / MEDIUM 0.7 / LOW 0.35)。
  減らした分は strength に移す。不確かな予測に最適化全体を賭けない。
- **フォールバック**: 相手データが無い / どのゲームにも対応付けできない → 勝利優先の重みで生成し、
  警告「対戦データ不足のため…通常の勝利優先 (戦力重視) で生成しました」。

## 4. 最終順位 (Match 勝率での再評価)

Match 勝率はゲーム勝率の非線形関数 (Poisson-binomial) なので探索の加法スコアにはできない。
探索 (Beam → B&B → 局所探索) で得た完全解のプールのうち、
**加法スコアが最良から `RERANK_SCORE_TOLERANCE` (スコア幅の 1.5%) 以内**のものを
`riskValue = P(win) + ½P(draw)` で再評価して選ぶ。公平性は許容幅で担保される
(公平性を大きく犠牲にした解はプールに入らない)。

リスクモード (将来用、UI 未提供): `NEUTRAL` (既定) / `CONSERVATIVE` (P(負けない)) / `AGGRESSIVE` (P(win))。

## 5. 相手の不確実性

相手の最頻オーダー 1 本ではなく、**分布に対する期待値**を最大化する
(`E[P_game] = Σ q(lineup)·P(…)`)。テスト: 55% 弱い選手 / 45% エースの枠で、最頻値だけを相手にした場合より
推定ゲーム勝率が低く評価されること、相手のエースの位置が変わるとオーダーも変わること。

## 6. Hard 制約

新しい項は Soft のみ。候補生成・`canPlace`・局所探索の `hardFeasible`・最終の `validateHardConstraints`
はすべて従来どおり。再評価も `hardFeasible` を通った解だけを対象にする。

## 7. 候補比較と説明

対戦相手最適化を選ぶと 4 案: 対戦相手最適化 / 勝利優先 / バランス / 公平性優先。
相手データがある限り全候補に `prediction` (推定 Match 勝率・引分・期待勝ちゲーム・信頼度・ゲーム別) が付く。

結果画面:
- 候補カード: 推定勝率 (信頼度)・期待勝数
- 対戦相手パネル: 推定 Match 勝率、期待勝ちゲーム、**通常の勝利優先との差 (+N pt)**、
  主な理由 (勝利優先から推定勝率が上がったゲーム上位 3 件と相手の予想)、信頼度、独立近似の注記
- ゲームカード: 「推定 61% ・ 中」
- 詳細分析: ゲームごとの「推定ゲーム勝率」とその理由、全体の「推定 Match 勝率」

表現: 「推定」「参考値」を使い、「確実」「必勝」等は使わない。設定で推定値の表示を消せる。
共有画像・テキストには推定値を含めない (共有層は予測を参照しない)。
