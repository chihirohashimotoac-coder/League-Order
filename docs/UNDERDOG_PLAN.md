# Underdog Plan (格上対策案)

標準案 (対戦相手最適化 = 推定 Match 勝率の最大化) でも勝ち目が小さい格上相手に、**1 タップで試せる案を 1 つだけ**
出す仕組み。実装: `src/optimizer/underdog.ts`、`generateOrder.ts` (`planUnderdog`)、
`src/components/n01/UnderdogPanel.tsx`、`src/state/orderSession.ts`。投順は
[`THROW_ORDER_MODEL.md`](./THROW_ORDER_MODEL.md) と同じ規則で決まる。

## 1. 表示条件 (すべて満たすときだけ)

| 条件 | 判定 | 満たさないとき (`underdogStatus.reason`) |
|---|---|---|
| 相手データがある | 標準案に推定がある | `no-opponent` |
| 標準案の推定 Match 勝率が **20% 以下** | 画面に出る整数 % (四捨五入) が 20 以下。**20% ちょうどは表示**、21% は非表示 | `not-underdog` |
| 相手データの信頼度が **MEDIUM 以上** | 相手ゲームの信頼度と相手オーダーモデルの信頼度の低い方 | `low-confidence` |
| 相手が格上 | 各ゲームの (相手の予想強度 − 自サイドの強度) の平均 > 0 | `not-stronger` |
| 意味のある改善 | どちらかの案の改善が共通尺度で **2pt 以上** (§3) | `no-improvement` |

「推定 Match 勝率 20.4%」は画面で 20% と出るので表示対象、「20.5%」は 21% と出るので対象外。
画面の数字と条件を一致させるための定義。

## 2. 内部で作る 2 案

同じエンジン・同じ重み・同じ Hard 制約・同じ公平性項・同じ偏りゲートで、目的だけを変えて 2 回探索する:

| 案 | 目的 | 探索での 1 ゲームの値 (加法的) |
|---|---|---|
| A | P(W ≥ 1) = 1 − Π(1 − p_g) の最大化 | `−ln(1 − p_g) / ln 100` (p は 0.99 で頭打ち)。和の最大化 = P(W≥1) の最大化 |
| B | E[W] = Σ p_g の最大化 | `p_g` |

- p_g は標準案と同じ推定 (投順モデル込み)。各ゲームの投順も同じ規則 (§6 の安全条件) で決まる。
- rerank (近い候補から最終 1 つを選ぶ段) と偏りゲートは **その案の目的の値** で判定する
  (A は P(W≥1)、B は E[W] / n。ゲートの閾値はどちらも 0..1 尺度で 2pt × steps² × 信頼度係数)。
- 標準案は変更しない。どちらの案も自動では適用しない。

## 3. どちらを出すか (比較方法)

2 つの目的はどちらも Match 1 回あたり 0..1 の報酬の期待値として書ける:

```
A: 1{W ≥ 1} の期待値 = P(W ≥ 1)
B: W / n    の期待値 = E[W] / n        (n = ゲーム数)

gain_A = P_A(W ≥ 1) − P_std(W ≥ 1)
gain_B = (E_B[W] − E_std[W]) / n
```

確率の差同士なので直接比べられる。

1. gain < 2pt (`UNDERDOG_MIN_GAIN` 0.02、許容 1e-9) の案は候補にしない。
2. gain の大きい方を出す。
3. 同点 (差 ≤ 1e-9) なら失う推定 Match 勝率の小さい方、さらに同点なら A。

性質: 1 ゲームの勝率を少し上げたときの増分は A が `Π_{h≠g}(1 − p_h)`、B が `1/n`。勝ち目の小さい相手では
`Π(1 − p_h)` が `1/n` より大きくなりやすく、**A が選ばれやすい** (§6 の合成データでは 31 件すべて A)。
B が選ばれるのは、B の案が多くのゲームを少しずつ上げ、A の案が特定のゲームに集中できない場合など。
単体テスト (`underdog.test.ts`) で B が選ばれる場合・同点の扱い・2pt 境界を確認している。

## 4. 画面 (1 タップ)

- 条件を満たすときだけ、結果画面の候補比較の下に「格上対策」パネルを出す。追加の入力・モーダルなし。
- 表示内容:
  - 見出し: `標準案の推定 Match 勝率 18%`
  - 理由: `1ゲーム以上取る確率を +6.0pt 改善 (61% → 67%)` または
    `期待勝ちゲーム数を 0.12 改善 (0.95 → 1.07 / 5)`
  - 失うもの: `標準案から失われる推定 Match 勝率 −1.2pt (18% → 17%)` (上がる場合は
    `推定 Match 勝率は標準案より +0.4pt`)
  - 出場の偏りが変わる場合: `出場回数の最大差 1 → 2 (出場なし: …)`
  - `相手データの信頼度 中。推定値であり、結果を保証するものではありません。自動では適用せず、標準案にいつでも戻せます。`
- ボタン: `格上対策案を試す` → その案に切り替え (Undo 可)。表示中は `標準案に戻す` → 1 タップで標準案へ。
- 切り替え後も手動編集・ロック・ゲームごとの再計算はそのまま使える (編集中は見出しに表示)。

## 5. 説明の方針

- 「必勝」「確実」は使わない。すべて推定値と明記。
- 失う推定 Match 勝率を必ず示す。
- 出場の偏りが増える場合は明示する (格上対策案は偏りゲートを自分の目的で通すため、偏りが増えることがある。§6)。

## 6. Backtest (`npm run backtest` の 6)

**モデルの推定値。** フィクスチャと架空チームのデータで、実戦の結果を示すものではない。

| データ | 結果 |
|---|---|
| フィクスチャのリプレイ 40 試合 | 標準案が 20% を超える 40 / 40 → 提案 0 (このフィクスチャは拮抗したリーグ) |
| 合成の格上戦 120 件 (シード 777、相手は平均 6–22 PPR 強い) | 提案 31、改善 2pt 未満 57、相手データ LOW 23、標準案 20% 超 9 |

提案された 31 件 (合成):

- 選ばれた案: A 31 / B 0。共通尺度の改善: 平均 +5.73pt、最大 +13.33pt。両案の改善の平均は A +5.73pt / B +0.96pt。
- P(W≥1): 64.7% → 70.5%。E[W]: 0.939 → 1.052。
- 失う推定 Match 勝率: 平均 −0.45pt (= 平均では上がる)、最大 +1.69pt。標準案は Match 値で偏りゲートを通し、
  格上対策案は自分の目的で通すため、格上対策案の方が偏りを許し、結果として Match 勝率も上がることがある。
- 出場回数の最大差 (spread): 1.00 → 1.61。**格上対策案は出場の偏りが大きくなりやすい** (画面で表示)。
- 規則違反の提案 (表示 20% 超・LOW・改善 2pt 未満): 0。Hard 制約違反: 0。
- 処理時間 (ノード上限のみ、4 候補 + 2 案): 中央値 97 ms、最大 1266 ms (環境依存)。

## 7. 限界

- 「格上」の判定はモデルの強さの差の平均。相手の当日のメンバー・作戦は分からない。
- 20% / 2pt は方針値で、実測で校正したものではない。
- 両案とも推定の独立ゲーム近似 (`PREDICTION_MODEL.md` §5) に依存する。ゲーム間の相関 (当日の調子) は入らない。
- 合成データで B が選ばれていないため、B の画面表示はテスト (`underdog.test.ts`、`UnderdogPanel.test.tsx`) でのみ確認している。
